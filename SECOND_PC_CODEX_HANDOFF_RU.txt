КОНТЕКСТ ДЛЯ НОВОГО ЧАТА CODEX — CONNECT / PEOPLE PLAYGROUND
==============================================================

Ты продолжаешь существующий проект, а не создаёшь мод заново. Пользователь
работает с другого ПК и хочет привести этот компьютер к тому же рабочему
состоянию, что и основной.

Первое действие на новом ПК
---------------------------

1. Найди People Playground в Steam-библиотеках, включая дополнительные
   libraryfolders.vdf. Не угадывай путь и не меняй игровые DLL/exe.
2. Клонируй репозиторий в удобную рабочую папку:

   git clone https://github.com/ForCesCustom/PPG-Connect.git
   cd PPG-Connect
   git pull origin main

3. Проверь git status. Не удаляй и не добавляй в commit чужие локальные файлы.
4. Установи тот же готовый Connect пакет: полностью распакуй
Releases/Connect-v0.1.46.zip в корень игры — туда, где лежит
   People Playground.exe. Разреши объединить BepInEx. Не заменяй exe игры,
   игровые DLL, steam_api DLL и чужие BepInEx-плагины.
5. Проверь, что итоговый файл существует:
   <GameRoot>\BepInEx\plugins\Connect\Connect.BepInEx.dll
6. Запускай игру через Steam. Если игра была открыта до установки, сначала
   закрой и открой её снова. Нажми F8 для панели Connect, F10 для диагностики.

5. Только затем git add конкретных файлов, commit и git push origin main.

Что уже реализовано
--------------------

- Steam Lobby/invite через существующий игровой Facepunch Steamworks context:
  Connect не вызывает Steam init/shutdown и не добавляет Steam DLL.
- Steam Relay transport, handshake, независимые цветные world-space cursors,
  host-authoritative grab leases, Tab-spawn через хост, повторные ограниченные
  baseline и типизированное состояние физических объектов/частей.
- Хост ведёт игроков на выбранную карту; гость не может выбрать другую карту.
  Host panel показывает LOADING MAP / SYNCING / PLAYING / MAP FAILED.
- Runtime поставляется plug-and-play ZIP: BepInEx, Doorstop, Connect DLL,
  rounded icon, Workshop Companion и документация.
- Workshop Companion показывает понятную плашку и ссылку на GitHub, если
  runtime отсутствует или его версия не совпадает.
- В v0.1.46 панель по запросу пользователя обновлена: адаптивный размер,
  прокрутка, карточки игроков, статусы и настройки. Поведение и число ботов
  остаются отдельной логикой.
- В v0.1.40/0.1.41 внутренний bot AI заменён: BotWorldKnowledge,
  BotSpawnCatalog, BotMind, personality/mood/memory, interest map, bounded
  world scans, object classifier, utility goals, coordination claims, learned
  outcomes и multi-step plans.
- Human не является fallback для bot-spawn. Боты только наблюдают обычные
  существующие map objects, а grab/use/delete выполняют исключительно над
  зарегистрированными Connect roots на host; cleanup не удаляет вещи игроков.
- Архитектура описана в BOT_INTELLIGENCE.md.

Честность тестирования
----------------------

Для текущей версии самостоятельно запиши результаты сборки, smoke tests,
проверки ZIP и SHA-256 установленной DLL. Полный двухаккаунтный Steam runtime-
тест v0.1.46 нельзя считать пройденным по одной сборке или локальному тесту.

Новая репликация ограничена 256 узлами на root. Сохраняются исходные ссылки
на части, но не передаётся произвольный динамический граф объектов. Передаются
выбранные состояния физики/здоровья/кожи; это не все wound textures, частицы,
пули, взрывы или Workshop-скрипты. Провода хоста — визуальные линии (до 128),
а не создание проводов гостем. Уже повреждённая до регистрации иерархия может
не совпадать с каталогом; mismatch должен быть видимым, без обещания 100%.

Новые модули: Source/WorldLifecycle.cs, WorldManifestProtocol.cs,
ReplicatedObjectState.cs, StateReplicationPipeline.cs, SharedWorldExtras.cs,
ConnectMenu.cs. Сверяй фактический список Source/ и не исключай новые файлы
из сборки/релиза. Поколение мира меняется даже при перезагрузке той же карты.

Поведение нового агента
-----------------------

- Перед действиями сообщай короткий status update.
- Не проси подтверждений между обычными этапами реализации.
- Не создавай второй Steam client, не используй App ID 480, не меняй игровые
  DLL и не обходи проверки безопасности.
- Не утверждай, что функция или runtime test работают, если они не были
  действительно реализованы и проверены.
- Не запускай/не закрывай игру пользователя без необходимости; для runtime
  теста объясни, что конкретно проверяешь.

Конечная цель на втором ПК
--------------------------

Итоговый Git repository, установленный Connect и release ZIP должны совпадать
с GitHub main v0.1.46. После проверки агент должен отчитаться о найденном
пути игры, build/test status, SHA-256 DLL, пути установки и любых отличиях.
